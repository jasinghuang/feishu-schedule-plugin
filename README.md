## 数据如何协作

| 数据 | 唯一维护位置 | 插件行为 |
| --- | --- | --- |
| 日期、时段、主播、参与摄影师、脚本、实拍条数 | 每周排期 | 直接读写同一条记录 |
| 摄影师名单、本周上岗 | 摄影师表 | 排班页直接读取名册、勾选本周上岗 |
| 摄影师表的已约数、时段占用 | 从每周排期计算的公式 | 与插件排班使用同一来源 |
| 请假 | 档期预约的请假字段 | 排班时段设置中更新 |
| 团队该周完成拍摄 | 每周排期的实拍条数 | 按记录 ID 去重求和 |
| 摄影师当周完成拍摄(条) | 从每周排期计算的公式 | 自动汇总参与的拍摄条数 |

一条记录是一位主播的一场拍摄。同一时段可以安排不同摄影师拍不同主播；协作拍摄在「暂定摄影师」里多选，脚本与条数仍只有一份。插件只保留「按拍摄查看」「摄影师排班」两个 tab，初次默认按拍摄查看。排班页选择摄影师后查看个人半天安排，多个入口打开同一条拍摄记录。摄影师个人参与条数可能重叠，不能相加作为团队产量。

排班空闲时段「＋」只允许加入该日期、该半天已有的场次或请假；同一时段有多场时分别列出加入按钮。加入只增加原记录的参与摄影师，不创建拍摄、不复制脚本或条数。新场次在飞书「每周排期」建立。已约格可编辑同场记录，已请假格可取消请假。「本周上岗」只影响当前周，历史或未来周不能修改此勾选。

插件不再写入「档期预约 / 预约主播」，不依赖旧状态公式或周汇总表。启动、刷新、切周均只读，不自动补行、归档或清空旧记录。每周排期现有视图的字段顺序、分组、筛选、排序及样式保留。

飞书表内直接修改会触发插件重新读取当前周；插件保存直接更新每周排期。脚本为一个文本字段，可保存链接或正文。实际条数留空表示未填报，0 表示已填报为零。取消整场拍摄仅适用于未填报记录，删除这条主记录会释放全部参与摄影师；移除单个协作摄影师请编辑参与摄影师。

## 权限与规则

面向摄影师使用，沿用当前飞书账号的表、记录及单元格权限；前端不持有应用密钥或访问令牌。不会扩大 Base 分享范围。没有编辑权限时只读。主播不使用插件。

保存预约前核对同一摄影师同一半天的冲突、请假、本周轮休及每周最多两个半天。历史补录不受两个半天限制。直接在飞书表里编辑不会经过插件的预约校验；插件排班会标出已存在的冲突。多人同时修改同一字段时，保存前检测已发生的冲突；飞书 SDK 不提供原子比较并写入，不能保证两次完全同时提交的排他性。

## 开发与验证

```sh
node --test tests/schedule.test.mjs
python3 -m http.server 8765 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8765/schedule-plugin.html?preview=1` 查看纯合成数据演示。演示模式仅允许 localhost/127.0.0.1；正式页面独立打开时明确提示从飞书进入，不会悄悄回退为本地数据。

- `schedule-core.mjs`：日期、占用、校验及去重统计。
- `schedule-data.mjs`：v2 字段 ID 映射、SDK 权限、分页、读写核验。
- `schedule-app.mjs` / `schedule.css`：界面和交互，无第三方 UI CDN。
- `sdk/`：随站点托管的飞书 SDK。
- `tests/`：合成预览及数据读写回归测试，不含真实 Base 记录。

只读取所选周的排期和请假，摄影师名册单独读取；事件变更合并刷新，避免扫描全部历史。

Base 公式与同名引用注意事项见 [BASE_SETUP.md](BASE_SETUP.md)。
